# 노드 태그·검색 설계

## 목적
노드에 색 있는 태그를 달아 생각을 주제별로 묶고, 태그나 내용으로 찾는다. 검색은 두 가지 쓰임을 다 받는다.
- 예전에 적어둔 메모 하나를 찾아가기 → 결과 목록에서 눌러 이동
- 같은 태그끼리 한눈에 보기 → 캔버스에서 해당하지 않는 노드를 흐리게

개인이 생각을 펼치는 보드라는 제품 방향(PRODUCT.md)에 맞춰, 하위 캔버스 안에 접어둔 노드까지 찾는 것이 차별점이다.

## 결정 사항 (사용자 확인)
- 모든 노드 종류(텍스트·이미지·캔버스·링크)에 태그를 단다. 태그는 속성 패널에서 붙이고 뗀다.
- 태그마다 **색**이 있고 사용자가 바꿀 수 있다.
- 노드를 여러 개 선택하면 태그를 한꺼번에 붙이고 뗄 수 있다.
- 검색하면 지금 캔버스에서 **해당하지 않는 노드가 반투명**해진다.
- 결과 목록 항목에 **마우스를 올리면 그 노드가 빛나며 강조**되고, **클릭하면 그 노드로 이동**한다.
- 캔버스 위 노드에는 태그를 **머리 오른쪽의 색 점(A안)** 으로 보여준다. 최대 3개, 넘치면 `+N`. 이름은 마우스를 올리면 보인다.
- 구현 방식은 **1번**: 루트 문서에 태그 목록, 노드에는 태그 ID. 검색은 브라우저에서 문서를 훑는다.

## 접근 방식 (검토한 세 가지)
1. **문서 안 태그 목록 + 노드에는 태그 ID (선택).** 지금처럼 문서 하나를 JSONB로 저장하는 구조에 그대로 얹힌다. Undo·자동 저장·충돌 처리·JSON 내려받기·복제가 손대지 않아도 따라온다. 이름·색 변경은 목록 한 곳만 고친다. 노드가 최대 1000개라 브라우저 검색이 타이핑 즉시 끝난다.
2. 노드에 태그 이름을 저장하고 색만 따로 둔다. 이름을 바꾸면 하위 캔버스까지 모든 노드를 고쳐야 하고 오타 태그가 갈라진다. 버렸다.
3. DB에 태그 테이블을 두고 서버에서 검색한다. 노드가 문서 JSON 안에 있어 테이블과 계속 맞춰야 하고 Undo·충돌 처리와 따로 논다. 이 규모에서 얻는 것이 없다. 버렸다.

## 데이터
```ts
// 루트 문서에만 있다. 하위 캔버스 문서는 이 목록을 공유한다.
WorkspaceDocument.tags?: TagDefinition[]

type TagDefinition = {
  id: string;            // uuid
  name: string;          // 1~30자, 앞뒤 공백 제거, '#'과 공백 없음
  color: ConnectionColor // 연결선·펜과 같은 8색 팔레트의 이름
};

NodeBase.tags?: string[] // TagDefinition.id 목록, 붙인 순서 유지
```
- 태그 이름은 프로젝트 안에서 대소문자 무시하고 겹치지 않는다(`UI`와 `ui`는 같은 태그).
- 제한: 프로젝트 태그 200개, 노드 하나에 태그 20개. 넘으면 화면 아래 안내(notice)로 알린다.
- 빈 목록과 태그 없는 노드는 저장하지 않는다(`tags` 필드 생략). 이전 문서는 그대로 열린다.
- 스키마 검사:
  - `tags` 목록은 깊이 0(루트)에서만 허용한다. 하위 문서에 있으면 거절한다.
  - 루트 `superRefine`에서 모든 노드(하위 포함)의 태그 ID가 목록에 있는지, 노드 안 중복이 없는지 확인한다.
  - 이름 중복(대소문자 무시)과 ID 중복을 거절한다.

## 태그 붙이기 (속성 패널)
- **노드 하나 선택:** "기본 정보" 아래에 "태그" 칸.
  - 붙은 태그는 색 점 + 이름 칩, 칩의 ✕로 뗀다.
  - 입력칸에 치면 기존 태그가 자동완성으로 뜬다(이름에 포함되면 후보, 최대 8개, 방향키·Enter로 고름).
  - 없는 이름에서 Enter → 새 태그를 만들어 붙인다. 앞의 `#`은 떼고 받는다.
  - 칩을 누르면 8색 팔레트가 떠서 그 태그의 색을 바꾼다(모든 노드에 반영).
- **여러 개 선택:** 지금 안내 문구 대신 "공통 태그" 칸.
  - 모두에 붙은 태그는 진한 칩, 일부에만 붙은 태그는 흐린 칩으로 보인다.
  - 흐린 칩을 누르면 나머지 노드에도 붙는다. ✕는 고른 노드 전부에서 뗀다.
  - 입력칸으로 붙이면 고른 노드 전부에 붙는다.
- 태그를 붙이고 떼는 조작 하나가 Undo 한 단계다.
- (설계자 판단) 여러 노드에 붙일 때 일부 노드가 이미 20개면 **자리 있는 노드에만 붙이고**, "노드 N개는 태그가 가득 차 붙이지 못했어요" 안내를 띄운다. 흐린 칩 채우기도 같다. 모두 가득 찼으면 아무것도 바꾸지 않는다(Undo 단계도 생기지 않음).
- 새 태그 색: 팔레트 8색 중 프로젝트에서 가장 적게 쓴 색, 같으면 팔레트 순서상 앞의 색.

## 태그 관리 (메뉴바 "태그")
- 파일·편집·보기 옆에 "태그" 메뉴. 프로젝트 태그 목록을 사용 노드 수와 함께 보여준다.
- 이름 바꾸기(인라인 입력, 중복이면 오류 표시), 색 바꾸기(팔레트), 삭제.
- 삭제는 "이 태그를 단 노드 N개에서 모두 떨어집니다" 확인 후, 목록과 모든 노드(하위 포함)에서 지운다. Undo로 되돌릴 수 있다.
- 노드에서 떼어 아무 노드도 안 쓰는 태그도 목록에는 남는다(관리 메뉴에서 지운다).

## 캔버스 표시
- 노드 머리 오른쪽에 태그 색 점(지름 8px)을 최대 3개, 넘치면 `+N`(12px Lichen).
- 점 묶음에 마우스를 올리면 태그 이름 목록 툴팁. 노드의 `aria-label`에 태그 이름을 덧붙인다.
- 제목이 길면 제목이 잘리고 점은 항상 보인다.

## 검색
- **열기:** 헤더의 돋보기 버튼, `Ctrl/Cmd+F`(입력칸 안에서도 편집기 검색이 열린다. 브라우저 찾기 대신). 캔버스 오른쪽 위에 떠 있는 패널.
- **검색어 규칙:**
  - 띄어쓰기로 나눈 낱말이 **모두** 맞아야 결과다(AND).
  - 그냥 낱말: 노드 제목, 텍스트 노드 본문, 링크 노드 주소·미리보기 제목, 태그 이름 중 하나에 포함되면 맞음. 대소문자 무시.
  - `#낱말`: 그 이름으로 **시작하는** 태그를 단 노드만. 패널에서 `#`을 치면 태그 자동완성이 뜬다.
- **범위:** 프로젝트 전체(하위 캔버스 포함). 입력 후 150ms 쉬면 다시 계산한다.
- **결과 목록:**
  - 지금 캔버스 결과를 먼저, 그다음 다른 캔버스 결과(얕은 순)를 보여준다.
  - 항목: 노드 이름(제목 없으면 `nodeDisplayName`), 종류, 태그 점, 다른 캔버스면 경로("디자인 시안 / 버튼").
  - 결과 개수 표시. 목록은 최대 100개까지, 넘치면 "검색어를 더 좁혀보세요".
- **캔버스 흐림 (지금 보고 있는 캔버스만):**
  - 맞지 않는 노드와, 양 끝이 모두 흐린 노드인 연결선은 불투명도 25%로 흐린다.
  - 결과를 품은 하위 캔버스 노드는 흐리지 않고 "N개" 배지를 단다.
  - 손그림은 흐리지 않는다.
  - 검색어가 비면 흐림이 없다.
- **호버:** 목록 항목에 마우스를 올리거나 키보드로 고르면 그 노드에 Moss Deep 두 겹 링과 잠깐(400ms) 밝아지는 빛을 준다. 다른 캔버스 결과면 그 결과를 품은 지금 캔버스의 캔버스 노드를 강조한다.
  - (설계자 판단) 결과가 지금 캔버스 아래에 있지 않으면(상위나 옆 캔버스) 캔버스에서는 강조하지 않는다. 목록 항목의 경로 표시로 위치를 알린다.
  - (설계자 판단) 캔버스 노드의 "N개" 배지는 그 안의 모든 깊이 결과 수이고, 캔버스 노드 자신이 맞아도 자기 자신은 세지 않는다. 자신이 맞는 캔버스 노드는 그 자체로도 결과 목록에 나온다.
  - 그래서 검색 결과마다 "지금 캔버스에 있는 가장 가까운 조상 노드 ID(없으면 null)"를 함께 계산한다.
- **클릭(또는 Enter):** 그 노드가 있는 캔버스로 이동(`writeCanvasPath`)하고, 노드가 화면 가운데에 오게 카메라를 옮긴 뒤 선택한다. 패널은 열린 채 남고 흐림은 새 캔버스 기준으로 다시 계산한다.
- **키보드:** 검색창에서 ↓/↑로 목록 이동, Enter로 이동, `Esc`로 패널 닫기(흐림 해제).
- 검색 상태는 화면 상태다. 문서·Undo·URL에 남지 않는다.

## 함께 동작해야 하는 것
- 노드 복제(`duplicateNodes`)는 태그 ID를 그대로 복사한다(같은 프로젝트).
- JSON 내려받기는 태그 목록이 루트에 있어 그대로 포함된다.
- 하위 캔버스 노드를 지워도 태그 목록은 남는다.
- 펜·지우개 모드에서도 검색 패널은 열린다. 결과를 클릭하면 선택 모드로 돌아간다.
- 대시보드 미리보기·발표 페이지는 바꾸지 않는다.

## 범위 밖
- 태그 기반 "모음 노드"(필터 노드, TODO 노드)와 노드 역할. 이 설계의 태그·검색 함수를 나중에 재사용한다.
- 태그 계층(부모·자식 태그), 태그 직접 색 고르기(팔레트 밖), 검색어 저장, 정규식 검색.
- 이미지 안 글자 검색.

## 빌더에게 맡기는 것
- 파일 나누기(예: `tags.ts` 순수 함수, `tag-input.tsx`, `search-panel.tsx`, `use-workspace-search.ts`)와 컴포넌트 구조.
- 검색 결과 계산 함수의 형태. 단, 문서 루트와 검색어를 받아 `{ node, path, … }` 목록을 돌려주는 순수 함수로 두어 단위 테스트한다.
- 강조 애니메이션의 세부 값(DESIGN.md 범위 안에서, 움직임 줄이기 설정 존중).

## 테스트
- 스키마: 태그 목록 왕복, 하위 문서의 `tags` 목록 거절, 없는 태그 ID 거절, 이름 중복(대소문자) 거절, 제한 초과 거절.
- 태그 조작: 여러 노드에 붙이기·떼기, 일부에만 있는 태그 채우기, 태그 삭제 시 하위 캔버스 노드에서도 빠짐, 새 태그 색 고르기.
- 검색: 낱말 AND, `#` 접두 태그, 대소문자 무시, 하위 캔버스 결과의 경로, 지금 캔버스 결과 먼저, 100개 제한.
- 편집기 단축키 테스트(`test-workspace-editing.ts`)에 `Ctrl+F`가 검색을 여는지 추가.
