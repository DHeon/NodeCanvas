# 체크리스트 노드 · 역할 설계

## 목적

캔버스 곳곳에 흩어진 "할 일"의 진행 상황을 한 노드에서 보고 체크한다. 노드에 **역할**을 붙이면 노드가 특정 동작을 갖게 되고, 그 역할을 모아 주는 노드가 결과를 집계한다. 첫 역할은 **할 일**, 첫 집계 노드는 **체크리스트**다.

역할과 태그는 다르다. 태그는 여러 개 붙이는 이름표이고 찾기·모아 보기에 쓴다. 역할은 노드에 하나만 붙고, 붙이면 노드가 무언가를 할 수 있게 된다(체크, 집계 대상). 나중에 질문·목표·일정 같은 역할이 같은 틀로 더해진다.

## 결정 사항 (사용자 확인)

- 새 노드 종류 **체크리스트**와 노드 속성 **역할**(없음 / 할 일)을 만든다.
- 할 일 노드를 체크리스트에 **연결선으로 이으면** 체크리스트 목록에 그 노드 제목이 뜬다.
- 체크는 체크리스트 목록에서도, 할 일 노드에 생기는 체크 버튼에서도 할 수 있고 둘은 같은 상태다. 진행률을 보여준다.
- 이미 있는 노드를 체크리스트에 연결해도 **역할이 자동으로 붙지 않는다**.
- 체크리스트 노드에서 **"이어서 만들기"로 만든 노드에는 할 일 역할이 자동으로 붙는다**.
- 체크리스트 안에서 **직접 항목을 쓸 수 있다**(B 방식). 진행률은 연결된 할 일과 직접 쓴 항목을 합쳐 계산한다.

## 접근 방식

- **선택: 체크 상태는 할 일 노드에, 직접 항목만 체크리스트에 저장. 목록은 그릴 때 연결선에서 만든다.** 선을 잇고 지우는 것만으로 목록이 맞고, 같은 할 일을 두 체크리스트에 이어도 상태가 하나라 어긋나지 않는다. 실행 취소도 문서 변경을 그대로 따라간다.
- 버림: 체크리스트가 연결된 노드 ID와 체크 상태를 따로 저장. 체크리스트 여러 곳에 같은 할 일을 이으면 상태가 둘로 갈리고, 선·노드를 지울 때마다 목록을 맞춰 고쳐야 한다.

## 데이터

```ts
// 역할은 나중에 종류가 늘어나도록 kind로 구분한다.
type NodeRole = { kind: "todo"; done: boolean };
NodeBase.role?: NodeRole;               // 없으면 역할 없음

type ChecklistItem = { id: string /* uuid */; text: string; done: boolean };
type ChecklistNode = NodeBase & { type: "checklist_node"; items: ChecklistItem[] };
WorkspaceNode = TextNode | ImageNode | CanvasNode | LinkNode | ChecklistNode;
```

- 역할은 체크리스트를 뺀 모든 노드 종류(텍스트·이미지·캔버스·링크)에 붙일 수 있다. **체크리스트 노드에는 역할을 붙일 수 없다**(스키마에서 거절).
- 직접 항목: 체크리스트 하나에 최대 **200개**, 글은 앞뒤 공백을 뺀 **1–200자**. 항목 ID는 그 체크리스트 안에서 겹치지 않는다. 빈 목록은 `items: []`.
- 새 체크리스트의 기본 제목은 "체크리스트"(내 판단), 기본 크기는 빌더가 정한다(목록이 몇 줄 보이는 정도).
- 이전 문서는 그대로 열린다(새 필드는 모두 선택 사항, 새 노드 종류는 새 문서에만 생긴다).

## 목록 만들기 (그릴 때 계산)

체크리스트 C의 목록 = **연결된 할 일** 다음에 **직접 항목**.

- 연결된 할 일: 같은 캔버스에서 C와 연결선으로 이어진(어느 쪽 끝이든) 노드 중 `role.kind === "todo"`인 것. 같은 노드와 선이 여러 개여도 한 번만 센다. 순서는 노드 위치(위 → 아래, 같으면 왼쪽 → 오른쪽).
- 직접 항목: 저장된 순서(추가한 순서).
- 진행률: 완료 수 / 전체 수. 전체가 0이면 진행률 대신 빈 상태 안내.
- 이 계산은 순수 함수로 둔다(테스트 대상).

## 체크리스트 노드 화면

```
┌ ☑ 이번 주 할 일                 ● ● ┐  ← 머리: 종류 아이콘, 제목, 태그 점
│ 3 / 6 완료 · 50%  ▓▓▓▓▓░░░░░        │  ← 진행률
│ ☑ 발표 자료 정리        ↗           │  ← 연결된 할 일(누르면 그 노드로 이동)
│ ☐ 버튼 색 정리          ↗           │
│ ☐ 우유 사기                    ×    │  ← 직접 항목(글 고치기·지우기)
│ + 항목 추가                         │
│ 역할이 없는 연결 노드 2개 · 할 일로 만들기 │  ← 있을 때만
└─────────────────────────────────────┘
```

- **진행률:** "N / M 완료" + 백분율 + 얇은 막대. 모두 끝나면 "모두 완료"로 바뀐다. 0개면 "항목을 추가하거나 할 일 노드를 연결해 보세요."
- **연결된 할 일 줄:** 체크 상자 + 노드 제목(제목이 없으면 기존 `nodeDisplayName` 규칙) + 노드라는 표시(↗ 같은 작은 아이콘). 체크하면 그 노드의 `role.done`이 바뀐다. 제목을 누르면 그 노드를 선택하고 화면 가운데로 옮긴다(검색 결과 고르기와 같은 동작).
- **직접 항목 줄:** 체크 상자 + 글. 글을 누르면 그 자리에서 고친다(Enter·포커스 이동으로 적용, Esc 취소, 비우고 적용하면 항목 삭제). 가리키거나 포커스하면 `×`(지우기)가 보인다.
- **항목 추가:** 맨 아래 입력칸. Enter로 추가하고 입력칸에 그대로 남아 연달아 쓸 수 있다. 한글 조합 중 Enter는 무시한다. 200개를 넘으면 알림.
- **역할 없는 연결 노드 안내:** C와 이어졌지만 역할이 없는 노드(체크리스트 노드는 제외)가 있으면 개수와 "할 일로 만들기" 버튼을 보인다. 누르면 그 노드들에 할 일 역할(`done: false`)을 한 번에 붙인다.
- 목록이 노드보다 길면 노드 안에서 스크롤한다(휠은 캔버스 확대가 아니라 목록 스크롤).
- 체크 상자·입력칸·버튼을 눌러도 노드를 끌지 않는다. 노드는 머리로 끈다(기존과 같음).

## 할 일 노드 화면

- 머리 제목 왼쪽에 둥근 체크 버튼. 누르면 `role.done`이 바뀐다. 이 버튼을 눌러도 노드가 끌리지 않는다.
- 완료된 할 일: 채워진 체크(Moss Deep) + 제목 취소선·Lichen 색.
- 노드의 접근성 이름에 "할 일, 완료됨/안 함"을 넣는다.

## 역할 정하기 (속성 패널)

- 체크리스트가 아닌 노드를 하나 고르면 "역할" 칸: **없음 / 할 일**. 할 일이면 "완료" 체크 상자도 보인다.
- 여러 노드를 고르면 "역할" 칸으로 한 번에 정한다(섞여 있으면 "여러 가지"로 보인다).
- 역할을 "없음"으로 바꾸면 완료 상태도 함께 사라진다.

## 만들기

- 도구 막대에 체크리스트 버튼, 단축키 **K**(내 판단: T·I·C·L·P·E가 이미 쓰인다).
- "이어서 만들기" 메뉴에 체크리스트 항목을 더한다.
- **체크리스트에서 이어서 만들기:** 출발 노드 중 체크리스트가 있으면 새 노드에 할 일 역할(`done: false`)을 붙인다. 새 노드가 체크리스트라면 역할을 붙이지 않는다(붙일 수 없으므로).

## 함께 동작해야 하는 것

- **실행 취소:** 체크 한 번, 항목 추가·글 고치기 한 번·지우기, 역할 바꾸기, "할 일로 만들기"는 각각 한 단계.
- **검색:** 체크리스트의 직접 항목 글도 검색된다(결과는 그 체크리스트 노드). 검색 패널의 종류 이름 "체크리스트".
- **태그:** 체크리스트 노드에도 태그를 붙일 수 있다.
- **복제(Ctrl+D)·이어서 만들기·다중 연결:** 역할과 항목이 그대로 복사된다. 복제한 할 일은 원래 체크리스트와 이어지지 않는다(선은 복제하지 않는 기존 규칙대로).
- **노드 삭제:** 할 일을 지우면 선과 함께 목록에서 빠진다. 체크리스트를 지워도 할 일 노드의 역할·상태는 남는다.
- **하위 캔버스:** 연결은 같은 캔버스 안에서만 되므로 목록도 같은 캔버스의 노드만 모은다.
- **대시보드 미리보기·노드 개수 제한(1000개)·저장 스키마**에 새 노드 종류가 반영된다.

## 범위 밖

- 체크리스트를 다른 체크리스트의 할 일로 넣기(나중에 "목표" 역할로).
- 직접 항목을 노드로 바꾸기, 목록 순서 끌어서 바꾸기.
- 마감일·담당 같은 할 일 정보, 다른 역할(질문·결정·일정 등).
- 다른 캔버스의 할 일 모으기.

## 빌더에게 맡기는 것

- 체크리스트 노드의 기본 크기, 아이콘 모양, 진행률 막대와 완료 연출(움직임 줄이기 설정 존중), 대시보드 미리보기 색.
- 역할 저장 함수와 목록 계산 함수의 이름·파일 배치.
- 속성 패널 안 "역할" 칸의 정확한 모양(기존 칸 나눔 선택 패턴을 따른다).

## 테스트

- 스키마: 역할 모양, 체크리스트 노드에 역할 거절, 항목 수·글 길이·ID 중복 거절, 이전 문서 통과.
- 목록 계산: 연결된 할 일만(역할 없는 노드 제외, 선 중복 한 번), 위치 순서, 직접 항목 뒤에 붙음, 진행률·빈 상태, 역할 없는 연결 노드 수(체크리스트 제외).
- 편집 동작: 체크 토글(목록·노드 버튼 같은 상태), 항목 추가·고치기·빈 글로 삭제·지우기, "할 일로 만들기" 한 단계, 체크리스트에서 이어서 만들면 역할이 붙고 다른 노드에서는 안 붙음.
- 검색: 직접 항목 글로 체크리스트가 찾아진다.
