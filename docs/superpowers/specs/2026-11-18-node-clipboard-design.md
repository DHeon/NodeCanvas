# 노드 복사·잘라내기·붙여넣기와 상황별 우클릭 메뉴 — 설계

날짜: 2026-11-18 · 브랜치: `feature/node-clipboard` (`feature/node-groups` 위)

## 왜

생각을 정리하다 보면 노드 묶음을 다른 자리·다른 하위 캔버스로 옮기거나 한 벌 더 쓰고 싶다. 지금은 Ctrl+D(제자리 옆 복제)뿐이고, 우클릭 메뉴는 노드 위에서만 그룹화/해제만 보여 준다. 사용자는 "그때그때 상황에 맞는" 우클릭 메뉴와, 그룹을 하나의 물건처럼 고르고 복사하는 흐름을 원한다.

## 목표

1. 노드 복사·잘라내기·붙여넣기: 메뉴와 Ctrl+C / Ctrl+X / Ctrl+V.
2. 작업영역 어디서든 우클릭하면 상황별 메뉴가 뜬다.
3. 그룹 선택: 그룹 멤버 전부가 선택되면 "그룹이 선택된 것"으로 보이고, 그룹째로 복사·붙여넣기 된다.
4. 그룹 영역 안에 붙여넣으면 그 그룹에 들어간다.

## 하지 않는 것

- 다른 탭·다른 프로젝트로 붙여넣기(앱 안 기억만, 새로고침하면 사라짐) — 사용자 선택 A.
- 그룹 안의 그룹(중첩 그룹).
- 연결선만 복사하기.
- 붙여넣기 결과를 시스템 클립보드의 리치 형식으로 다른 앱에 보내기(글만 보냄).

## 하면 안 되는 것(실패로 보는 것)

- 글을 쓰는 칸에서 Ctrl+C/X/V가 노드를 복사·붙여넣기 해 버림.
- 노드를 복사해 둔 뒤 다른 곳에서 주소·이미지를 복사했는데 Ctrl+V가 옛 노드를 붙여넣음.
- 붙여넣기가 스키마를 깨서 저장 실패(ID 중복, 없는 groupId, 한도 초과).
- 붙여넣기·잘라내기가 실행 취소 두 번 이상으로 쪼개짐.

## 결정 사항

### 접근: 클립보드 범위 — A(앱 안) 선택

| 안 | 내용 | 대가 |
|---|---|---|
| **A (선택)** | 복사한 노드를 앱 메모리에 둔다. 같은 탭이면 다른 하위 캔버스에도 붙여넣기 | 새로고침·다른 프로젝트에서는 사라짐 |
| B | 시스템 클립보드에 노드 데이터를 실어 탭·프로젝트를 넘나듦 | 이미지 권한, 외부 데이터 검증 — 작업이 큼 |

### 접근: 그룹 선택 판단 — A(파생) 선택

| 안 | 내용 | 대가 |
|---|---|---|
| **A (선택)** | 따로 상태를 두지 않는다. 어떤 그룹의 멤버 **전부**가 `selectedNodeIds`에 있으면 그 그룹이 선택된 것 | 범위 선택으로 멤버를 다 감싸도 그룹 선택으로 보임(의도된 일관성) |
| B | `selectedGroupIds`를 따로 둠 | 옮기기·삭제·방향키·속성 패널을 그룹용으로 따로 만들어야 함 |

A이므로 옮기기·방향키·삭제·태그·속성 패널은 지금처럼 노드 선택으로 동작한다.

### 그룹 선택 표시

- `selectedGroupIds(document, selectedNodeIds)` = 멤버가 1개 이상이고 멤버 전부가 선택된 그룹들.
- 선택된 그룹의 멤버 노드는 노드 선택 표시(진한 테두리·그림자)를 **숨긴다**. `NodeFrame`의 `selected`를 false로 넘기되, 접근성 이름에는 "선택됨"이 남도록 별도 처리(빌더 재량: `selected`와 `showSelection`을 나누는 식).
- 그룹 영역에 선택 표시: 테두리를 `border-moss-deep`으로, 두께 2px, 이름 탭도 진하게. 끌어 넣기 대상 표시(`joinTargetId`)와 구분되게(대상 표시는 지금의 링·배경).
- 이름 탭 클릭: 그룹 선택(멤버 전부로 선택 교체). **Shift+탭 클릭**: 그 그룹의 멤버를 선택에 더하고, 이미 그 그룹이 선택돼 있으면 빼기(토글). 끌기는 지금처럼 탭 그룹 + (Shift면) 기존 선택을 함께 끈다.
  - 이것은 노드 그룹 작업 때의 결정("Shift+탭 클릭은 선택을 바꾼다")을 뒤집는다.
- 그룹 멤버 노드 하나를 클릭하면 그 노드만 선택(지금 그대로) → 멤버가 둘 이상인 그룹이면 그룹 선택 표시는 사라지고 그 노드 표시가 보임.
- (설계자 판단) 멤버가 1명인 그룹은 그 노드를 클릭해도 정의대로 그룹 선택으로 보인다(파생 규칙 A의 일관성). 그 노드를 복사하면 그룹째 복사된다.

### 복사 (Ctrl+C, 메뉴 "복사")

- 선택이 없으면 아무것도 안 함.
- 앱 클립보드(워크스페이스 컴포넌트의 ref, 탭 안에서만)에 저장:
  - `nodes`: 선택된 노드의 깊은 복사본(하위 캔버스 포함). 원래 ID 그대로 둔다 — 붙여넣을 때 새 ID를 만든다.
  - `connections`: 양 끝이 모두 선택된 노드인 연결선.
  - `groups`: 선택 안에서 **통째로 선택된** 그룹들(id, title). 일부만 선택된 그룹의 멤버는 그룹 정보 없이 낱개 노드로 취급(`groupId` 삭제).
  - `text`: 시스템 클립보드에 넣을 글. 노드들의 제목·본문 글을 위치 순(위→아래, 왼→오른)으로 빈 줄로 이어 붙임. 비면 `노드 N개`.
- 키보드 Ctrl+C는 `copy` 이벤트에서 처리해 `clipboardData.setData("text/plain", text)` 후 `preventDefault` (권한 필요 없음). 메뉴 "복사"는 `navigator.clipboard.writeText(text)`를 시도하고 실패해도 무시(앱 클립보드는 이미 저장됨).
- 메모리의 `text`는 붙여넣기 때 "나중에 복사한 쪽" 판단에 쓴다(아래).

### 잘라내기 (Ctrl+X, 메뉴 "잘라내기")

- 복사 + 선택 삭제. 삭제는 기존 `deleteSelection` 규칙을 따른다(내용 있는 캔버스 노드면 확인 창, 취소하면 복사만 된 상태로 남아도 됨 — 빌더 재량으로 복사도 취소 가능). 실행 취소 한 단계.
- 그룹 멤버가 모두 지워지면 그룹은 기존 정리(`pruneEmptyGroups`)로 사라진다.

### 붙여넣기 (Ctrl+V, 메뉴 "붙여넣기")

- **위치**: 붙여넣는 노드 묶음의 경계 상자 **가운데**를 기준점에 맞춘다(묶음 안 배치는 유지).
  - 메뉴: 우클릭한 자리(캔버스 좌표).
  - Ctrl+V: 마지막으로 뷰포트 위에서 본 포인터 자리. 포인터가 뷰포트 밖에 있으면(마지막 `pointerleave` 이후) 화면 가운데.
  - 유한 캔버스면 묶음 전체를 같은 양만큼 밀어 캔버스 안에 들어가게(묶음이 캔버스보다 크면 왼쪽·위 기준).
- **새 ID**: 모든 노드(하위 캔버스 포함)·연결선·그룹에 새 ID. 기존 `node-clone.ts`의 복제 로직을 재사용해 순수 함수로 만든다(예: `pasteClipboard(root, path, clip, point, makeId)` → `{document, nodeIds} | {error}`).
- **그룹**:
  - 클립의 `groups`는 새 ID, 같은 이름으로 새로 만들고 해당 노드들의 `groupId`를 새 ID로 바꾼다.
  - 그룹이 없는(낱개) 노드는 기준점이 기존 그룹 영역 안이면(`groupAtPoint`, 붙여넣기 **전** 문서 기준) 그 그룹에 들어간다. 통째로 복사한 그룹은 다른 그룹에 들어가지 않는다(중첩 없음).
  - 그룹 한도 200을 넘으면 오류 문구 `그룹은 공간마다 200개까지 만들 수 있어요.`로 거절(아무것도 안 붙임).
- **한도**: 노드 수(`MAX_WORKSPACE_NODES`, 프로젝트 전체, 하위 포함), 그림 점(`MAX_DRAWING_POINTS`), 연결선(`MAX_CONNECTIONS`)은 Ctrl+D 복제와 같은 문구·규칙. 캔버스 깊이: 클립에 캔버스 노드가 있고 붙여넣을 공간 깊이 + 그 노드 안 깊이가 `MAX_CANVAS_DEPTH`를 넘으면 거절, 문구는 빌더 재량(기존 깊이 문구가 있으면 그대로).
- 붙여넣은 노드들이 새 선택이 된다(그룹째 붙였으면 자연히 그룹 선택 표시). 연결선 선택은 해제. 실행 취소 한 단계.
- **나중에 복사한 쪽 따르기**(Ctrl+V): `paste` 이벤트에서
  1. 이미지 파일이 있으면 → 지금처럼 이미지 노드.
  2. `text/plain`이 앱 클립보드의 `text`와 같으면 → 노드 붙여넣기.
  3. 아니면 → 지금처럼(주소면 링크 노드, 아니면 아무것도 안 함).
  - (설계자 판단) 메뉴 "복사"에서 `navigator.clipboard.writeText`가 실패하면 앱 클립보드에 `systemSynced=false`를 표시한다. 이때 Ctrl+V는 이미지 파일이 없으면 시스템 글과 상관없이 노드를 붙인다(다음 성공한 복사에서 표시 해제).
  - 메뉴 "붙여넣기"는 시스템 클립보드를 읽지 않고 앱 클립보드를 붙인다(권한 창 피함). 앱 클립보드가 비면 흐리게(disabled).
- 붙여넣는 곳이 복사한 곳과 다른 하위 캔버스여도 된다.

### 상황별 우클릭 메뉴

`NodeContextMenu`를 일반 메뉴로 넓힌다(항목 목록을 받는 형태 — 빌더 재량). 기존 열기 위치·화면 안 당기기·화살표·Esc·바깥 누르기 닫기는 유지.

| 우클릭한 곳 | 메뉴 항목(순서) |
|---|---|
| 노드 위(선택에 없으면 그 노드만 선택) | 잘라내기 · 복사 · 붙여넣기 · 구분선 · 그룹화 · (그룹 멤버가 하나라도 있으면) 그룹화 해제 |
| 그룹 이름 탭 위 | 그 그룹 선택(이미 선택에 포함돼 있으면 그대로) 후 위와 같은 메뉴 |
| 빈 곳(그룹 영역 안 빈 곳 포함), 선택 있음 | 선택 유지, 위와 같은 메뉴. 붙여넣기 기준점은 우클릭 자리 |
| 빈 곳, 선택 없음 | 붙여넣기만 |
| 글을 쓰는 칸(input, textarea, contenteditable)에서 **글자가 드래그로 선택돼 있을 때** | 잘라내기 · 복사 · 붙여넣기 — 글자 대상 |
| 글 칸이지만 고른 글자가 없음(커서만) | 그 칸이 노드 안이면 노드 위 우클릭과 같음, 노드 밖 칸(속성 패널 등)이면 메뉴 없이 브라우저 메뉴도 막음 |

- 항목 옆 단축키 표시: Ctrl+X, Ctrl+C, Ctrl+V, G, Shift+G (Mac은 ⌘).
- 선택이 연결선뿐이면 노드 메뉴 대신 "빈 곳, 선택 없음"과 같게.
- 펜·지우개 도구일 때, 제스처 중일 때는 메뉴를 열지 않는다(브라우저 메뉴도 계속 막음).
- 메뉴 키 / Shift+F10: 선택 있으면 지금처럼 첫 노드 근처, 없으면 화면 가운데에 "붙여넣기만" 메뉴.
- **글 칸 메뉴**:
  - 열 때 칸의 선택 범위를 기억해 둔다.
  - 잘라내기·복사: 선택된 글이 없으면 흐리게. `navigator.clipboard.writeText` 후 잘라내기는 그 범위를 지운다(React가 아는 변경이 되도록 `document.execCommand("insertText")` 또는 `"delete"` 사용 — 브라우저 실행 취소에 남음).
  - 붙여넣기: `navigator.clipboard.readText()` → 성공하면 기억한 범위에 `insertText`. 거절·실패하면 조용히 닫고 알림 문구 `붙여넣기는 Ctrl+V를 써 주세요.`(빌더 재량으로 notice 사용).
  - 닫으면 그 칸으로 포커스를 돌린다.
  - 이것으로 글 칸의 브라우저 기본 메뉴(맞춤법 추천)는 사라진다 — 사용자 요청.
- 노드 위 우클릭에서 노드 내부의 읽기 전용 글(예: 링크 미리보기)은 노드 메뉴로 취급.

### 키보드

**글 칸 규칙(사용자 선택 A)**: 텍스트 노드 본문은 늘 켜져 있는 글 칸이라, "글 칸에 포커스"만으로 글자 대상이라고 보지 않는다.

- Ctrl/⌘+C, X: 포커스가 글 칸이 아니거나, **노드 안의 글 칸인데 고른 글자가 없으면**(selectionStart === selectionEnd) 노드용. 고른 글자가 있으면 브라우저 기본(글자).
- 노드 밖 글 칸(속성 패널, 검색 등)은 늘 브라우저 기본.
- Ctrl/⌘+V: 글 칸에 포커스가 있으면 늘 브라우저 기본(글자 붙여넣기). 글 칸이 아닐 때만 노드 붙여넣기 판단.
- Ctrl+C/X는 `copy`/`cut` 이벤트로 처리(뷰포트에서 받음). 선택이 없으면 기본 동작 그대로.
- 단축키 도움말(`shortcut-help.tsx`)에 `Ctrl + C / X / V — 노드 복사 / 잘라내기 / 붙여넣기`, 우클릭 줄은 `우클릭 · 메뉴 키 — 상황별 메뉴`로.

## 남겨 둔 것(빌더 재량)

- 클립보드 타입과 순수 함수 이름·파일 위치(예: `node-clipboard.ts`).
- 메뉴 컴포넌트를 어떻게 일반화할지, 아이콘 여부.
- 그룹 선택 표시의 정확한 스타일(디자인 토큰 안에서).
- 붙여넣기 거절 문구 중 정해지지 않은 것.

## 확인 방법

- 순수 함수 테스트: 복사 묶음 만들기(통째 그룹/일부 그룹), 붙여넣기 위치(가운데 맞춤, 유한 캔버스 당기기), 새 ID 고유, 그룹 새로 만들기, 그룹 영역 안 낱개 붙여넣기 → 가입, 통째 그룹은 가입 안 함, 한도 거절, 결과가 스키마 통과.
- 워크스페이스 하네스 테스트: Ctrl+C/X/V(이벤트), 붙여넣기 한 단계 실행 취소, 잘라내기 한 단계, 우클릭 상황별 항목, "나중에 복사한 쪽" 판단, 글 칸에서 노드 복사 안 함.
