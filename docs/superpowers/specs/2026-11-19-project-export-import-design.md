# 프로젝트 내보내기·불러오기 (.nono)

## 왜

프로젝트를 파일로 백업하고, 다른 계정·다른 서버에서 그대로 되살리고 싶다. 지금 "JSON으로 내려받기"는 문서만 담고 이미지는 서버의 이미지 ID만 남아, 다른 곳에서 불러오면 이미지가 깨진다.

## 정한 것 (사용자)

- 전용 확장자 `.nono` 하나로 내보내고 불러온다. XML·형식 고르기는 하지 않는다.
- `.nono`는 zip 압축 파일이다(문서 + 이미지 파일).

## Approaches

| 방식                                       | 장단점                                                 | 결정     |
| ------------------------------------------ | ------------------------------------------------------ | -------- |
| `.nono` = zip(`document.json` + `images/`) | 이미지가 원본 그대로라 작다. 압축 라이브러리 하나 추가 | **선택** |
| `.nono` = JSON 한 파일(이미지 base64)      | 가장 간단, 파일이 약 33% 커진다                        | 기각     |
| XML                                        | 문서가 이미 JSON이라 변환만 늘고 이미지 문제는 그대로  | 기각     |

## 파일 형식 (버전 1)

```
제목.nono (zip)
├── manifest.json   { "format": "nono", "version": 1, "title": "...", "exportedAt": "ISO 시각" }
├── document.json   루트 문서(하위 캔버스·태그·그룹 포함, 저장 형식 그대로)
└── images/<이미지ID>.webp   문서가 참조하는 이미지마다 하나
```

- 이미지는 이미 webp라 다시 압축하지 않고 담는다(store). JSON만 deflate.
- `version`이 1이 아니면 거절한다("이 앱보다 새 버전에서 만든 파일이에요"). 나중에 형식이 바뀌면 여기서 변환한다.

## 내보내기

- 작업 공간 메뉴 "파일" → ".nono로 내보내기". 기존 "JSON으로 내려받기" 자리를 바꾼다(충돌 패널의 "내 편집 내려받기"는 그대로).
- 브라우저에서 만든다: 지금 화면의 문서(저장 전 편집 포함)를 담고, 참조 이미지를 기존 이미지 주소에서 받아 함께 묶어 내려받는다.
- 이미지 하나를 못 받으면 내보내기를 멈추고 알림을 띄운다(이미지 빠진 백업을 조용히 만들지 않는다).
- 파일 이름: 프로젝트 제목(파일 이름에 못 쓰는 글자는 `_`) + `.nono`.

## 불러오기

- 대시보드(프로젝트 목록)에 "불러오기" 버튼, 작업 공간 "파일" 메뉴에도 "불러오기". 파일 선택 → 업로드.
- 서버 `POST /api/projects/import`가 처리하고, **새 프로젝트**를 만든 뒤 그 프로젝트로 이동한다(기존 프로젝트를 덮어쓰지 않는다).
- 서버 처리 순서:
  1. 로그인·Origin 검사(기존 저장 API와 같다).
  2. 크기 제한: 업로드 60MB, 풀었을 때 합계 200MB, 항목 수 1100개. 넘으면 거절(압축 폭탄 방지).
  3. `manifest.json` 형식·버전 검사.
  4. `document.json`을 기존 문서 검사 규칙(`workspaceDocumentSchema`)으로 검사. 틀리면 거절.
  5. 이미지 노드마다 `images/<ID>.webp`를 기존 이미지 처리(`normalizeImage`, 형식 확인·다시 인코딩)로 통과시켜 새 프로젝트의 이미지로 저장하고, 문서 속 이미지 ID·크기를 새 값으로 바꾼다. 같은 이미지를 여러 노드가 쓰면 한 번만 저장한다.
  6. 파일에 없는 이미지는 그 노드를 "빈 이미지 노드"(`image: null`)로 두고, 불러온 뒤 "이미지 N개를 찾지 못했어요" 알림.
  7. 프로젝트·이미지·문서를 한 트랜잭션으로 만든다(중간에 실패하면 아무것도 남지 않는다).
- 제목: manifest의 제목(앞뒤 공백 정리, 120자 제한), 없으면 파일 이름.

## 하지 않는 것

- PNG·PDF·Markdown 같은 보기용 내보내기(나중에 따로).
- 기존 프로젝트에 합치기·덮어쓰기.
- 다른 앱 형식 불러오기.

## 빌더에게 맡기는 것

- 압축 라이브러리: `fflate`(브라우저·서버 둘 다 쓰는 작은 라이브러리).
- 압축·풀기와 형식 검사는 순수 함수 파일(`project-archive.ts`)로 두고 테스트한다.
- 버튼 문구·알림 문구의 세부.
