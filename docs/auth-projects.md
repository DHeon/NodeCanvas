# 로그인과 사용자별 프로젝트

## 확인 순서

1. Docker Desktop을 켜고 `docker compose up -d db`를 실행합니다.
2. `npm run dev`로 앱을 실행합니다.
3. `.env`의 `BETTER_AUTH_URL`과 동일한 주소(현재 `http://localhost:3000`)에서 회원가입 후 로그인합니다.
4. 대시보드에서 새 프로젝트 이름을 입력하고 생성합니다.
5. 프로젝트 목록으로 돌아온 뒤 로그아웃합니다.
6. 다른 계정으로 로그인하면 앞 계정의 프로젝트는 목록에서 보이지 않고, URL로 직접 접근해도 404입니다.

회원가입 시 자동 로그인은 기존 설정대로 꺼져 있습니다. 로그인 실패 메시지는 계정 존재 여부를 구분하지 않습니다.
HTTP IP 접속은 localhost와 다른 origin입니다. 인증 테스트는 우선 설정된 localhost 주소로 진행하세요.
임의 origin을 허용하거나 CSRF 보호를 끄지 않습니다.

## 파일 역할

- `src/features/auth/login-form.tsx`: 이메일/비밀번호 검증, Better Auth 로그인, 제출 중 상태와 실패 안내
- `src/features/auth/login-destination.ts`: 로그인 후 이동할 내부 경로 허용 목록
- `src/features/auth/logout-button.tsx`: 세션 종료 후 로그인 화면으로 이동
- `src/lib/session.ts`: 서버에서 실제 세션 확인, 비로그인 사용자를 로그인 화면으로 이동
- `src/app/(app)/dashboard/page.tsx`: 세션 사용자 ID로 소유 프로젝트 조회
- `src/app/(app)/projects/[projectId]/page.tsx`: ID 형식과 소유자 확인 후 작업 공간 표시
- `src/features/projects/actions.ts`: 서버에서 제목 검증 및 세션 사용자 소유의 프로젝트 생성

페이지마다 DB 조회 전에 세션을 확인합니다. 레이아웃에서 메뉴만 숨기는 방식이 아닙니다.
프로젝트 생성도 별도로 인증하며, 클라이언트가 전달한 ownerId는 사용하지 않습니다.
로그인/로그아웃 후에는 전체 페이지 이동으로 이전 계정의 클라이언트 라우터 캐시를 비웁니다.

## 통합 테스트

로컬 DB와 서버가 실행된 별도 터미널에서:

```powershell
npx tsx scripts/test-auth-projects.ts
```

테스트는 로컬 주소만 허용하며, 무작위 이메일의 임시 사용자 두 명을 생성합니다.
로그인, 잘못된 비밀번호, 프로젝트 생성, 소유자 위조 방어, 계정별 목록 분리,
타인/없는/잘못된 프로젝트 ID 접근 차단, 로그아웃 후 세션 거부를 HTTP 요청으로 검사합니다.
마지막에 이번 실행에서 만든 사용자와 연결된 프로젝트/세션만 삭제합니다.
테스트 실행 중 프로세스를 강제로 종료하면 정리 코드가 실행되지 않을 수 있습니다.
이 검사는 브라우저 시각적/클릭 테스트를 대체하지 않습니다.

## 이번 범위에 포함되지 않은 것

- 캔버스 문서 저장/불러오기와 자동 저장은 다음 단계입니다.
- 새 프로젝트의 메타데이터(이름, 소유자)는 DB에 저장되지만, 노드 내용은 아직 메모리에만 있습니다.
- 기존 `demo@nono.local` 및 테스트 프로젝트를 일반 계정으로 이전하지 않았습니다.
- 발표 페이지에서 고정된 테스트 프로젝트를 여는 링크/iframe도 이제 소유자 검사를 받습니다.
  독립 발표 데모 `/pres/demo`는 기존대로 사용할 수 있습니다.
