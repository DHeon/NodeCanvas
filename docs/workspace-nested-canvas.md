# 중첩 캔버스 노드

## 사용

- 왼쪽 도구 막대의 캔버스 버튼으로 `캔버스 노드`(기본 제목 "새 작업 공간", 260×140)를 만든다. 노드 안에는 독립된 하위 작업 공간이 하나 들어 있다.
- 노드의 "열기" 버튼으로 하위 공간에 들어간다. 경로 표시줄의 "상위 작업 공간", 경로 항목, Alt+↑, 브라우저 뒤로 가기로 돌아온다. 헤더 제목은 현재 공간의 제목을 보여준다.
- 현재 공간 경로는 URL `?canvas=<노드 ID>.<노드 ID>`에 둔다. 새로고침해도 같은 공간이 열리고, 없는 경로는 남아 있는 가장 가까운 상위 공간으로 고쳐진다.
- 캔버스 노드 카드에는 하위 노드 수("노드 N개" / "비어 있음")를 보여준다.
- 하위 공간은 캔버스 크기·무한 모드 설정, 노드, 연결선을 각자 따로 가진다. 연결선은 같은 공간 안의 노드끼리만 잇는다.
- 공간마다 마지막 카메라 위치·확대 비율을 기억한다(새로고침 전까지, 저장하지 않음). 공간을 옮기면 선택은 해제된다.
- 내용이 있는 캔버스 노드를 지우면 확인 창을 띄운다. Undo로 하위 문서 전체를 복구할 수 있다.

## 제한

- 최대 깊이 `MAX_CANVAS_DEPTH = 8`. 이 깊이의 공간에서는 캔버스 노드를 추가할 수 없다고 안내하고, 서버도 더 깊은 입력을 거절한다.
- 노드 수 `MAX_WORKSPACE_NODES = 1000`은 공간별이 아니라 **프로젝트 전체 합계**에 적용한다.
- 노드 ID는 프로젝트 전체에서 고유해야 한다.

## 구조

- `types.ts`: `WorkspaceNode = TextNode | ImageNode | CanvasNode`. `CanvasNode.document`가 하위 `WorkspaceDocument`다.
- `workspace-tree.ts`: 경로(캔버스 노드 ID 배열) 해석 `resolveWorkspacePath`, 대상 공간과 조상만 새 객체로 바꾸는 `updateWorkspaceAtPath`, 전체 노드 순회 `walkWorkspaceNodes`.
- `workspace.tsx`: 이력은 루트 문서 하나를 가진다. `canvasPath` 상태로 현재 공간을 고르고, 기존 편집 함수는 `setWorkspace`를 거쳐 현재 공간만 수정한다. Undo로 현재 공간이 사라지면 렌더 중에 남아 있는 가장 가까운 상위 공간으로 경로를 줄인다.
- `canvas-node-view.tsx`: 캔버스 노드 본문(열기 버튼).
- `workspace-schema.ts`: `documentSchemaAtDepth`로 깊이별 스키마를 재귀 구성하고, 루트에서 전체 노드 수와 ID 중복을 검사한다.
- `use-image-uploads.ts`: 업로드 시작 시의 경로를 기억해, 완료 시 사용자가 다른 공간으로 이동했어도 원래 공간의 노드에만 적용한다.

## 저장

- 기존과 같이 루트 문서 전체를 `project.document` JSONB 한 곳에 저장한다. 버전도 하나라 하위 공간을 고쳐도 같은 자동 저장·충돌 검사(409)를 쓴다. DB 마이그레이션은 필요 없다.
- PUT 시 서버는 모든 하위 공간의 이미지 참조까지 순회하며 이 프로젝트의 자산인지 검증한다.

## 알려진 한계·후속 작업

- Undo/Redo 이력이 프로젝트 전체 하나다. 하위 공간 안에서 Ctrl+Z를 누르면 다른 공간에서 한 마지막 변경이 되돌려질 수 있다.
- 캔버스 노드 카드는 하위 내용의 미니어처를 보여주지 않는다. 더블클릭 진입도 아직 없다.
- 이력 비교가 루트 문서 전체 `JSON.stringify`라 문서가 커지면 비용이 함께 커진다.
- 깊이 제한에 걸린 공간에서 캔버스 노드를 추가하려 하면 화면 아래 안내가 뜬다(툴바 버튼은 `aria-disabled`).
- 삭제된 캔버스 노드 안의 이미지 자산도 다른 이미지와 같이 프로젝트 삭제 때까지 남는다.

## 검증

```powershell
node --import tsx --test scripts/test-workspace-tree.ts
node --import tsx scripts/test-workspace-images-integration.ts
```

단위 테스트는 중첩 문서 왕복, 다른 공간 간 연결·ID 중복 거절, 깊이·전체 노드 수 제한, 경로 수정의 구조 공유, 삭제 후 Undo 복구, 업로드 결과 경로 고정을 검사한다. 통합 테스트(로컬 서버·Docker DB 필요)는 중첩 문서 저장·재조회, 하위 공간 안 다른 프로젝트 이미지 참조 거절, 오래된 버전 저장 충돌을 검사한다.
